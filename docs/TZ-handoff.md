# Доработка помощника — 14 октября 2026

## Что исправлено

Существующий компонент сохранён. По последующему уточнению блок расположен сразу после заголовка статьи, основная кнопка называется «Получить ответ». Внутри карточки гостевого ответа появились три декоративные размытые строки с плавным исчезновением. Настоящее продолжение не помещается в гостевой HTML или открытые поля API: оно раскрывается из зашифрованного билета после серверной проверки входа, без нового вызова модели.

Формы можно закрывать и переключать без потери вопроса и начала ответа. Демо-вход сохраняется в HttpOnly cookie; обновление страницы очищает сообщения и черновик, но сохраняет вход. «Новый диалог» также очищает интерфейс и создаёт новый идентификатор сессии, не удаляя историю на сервере. Повторная отправка, включая Ctrl+Enter при ошибке, не создаёт дубликат ожидающего вопроса.

Главная страница теперь выбирает настоящие адаптеры при `ASSISTANT_MODE=real`; `/demo` всегда остаётся демонстрацией. `getArticleContext(articleSlug)` получает содержательный текст соответствующей статьи на сервере. В реальную модель уходят системный промпт, статья, все предыдущие сообщения с исходными ролями и полными ответами, затем новый вопрос. Поддержаны обе статьи из текущего реестра; неизвестная статья отклоняется. При подключении CMS нужно заменить реестр её серверным резолвером и передавать в компонент slug открытой статьи; ключ компонента должен включать slug.

Проверены выбор реального API интерфейсом, проверка cookie, отказ демо-токену, отсутствие закрытого текста в гостевом API, раскрытие того же ответа, порядок ролей, две статьи, полная серверная запись, привязка к пользователю и сохранность после перезапуска сервера. ## Что осталось демонстрационным на Vercel

Ответы — серверные заготовки, вход и регистрация — тестовые, аккаунты и письма не создаются. Поля демонстрационной формы не отправляются. События демо хранятся в памяти страницы. Постоянная база переписок в опубликованном демо не подключена. Зашифрованный билет служит для раскрытия ответа и **не является архивом переписки**.

## Что подключить разработчикам Бухэксперта

1. **Модель.** Серверные `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`, приватный `ASSISTANT_TOKEN_SECRET`. Режим `ASSISTANT_MODE=real`, включение пилота и его дата по `.env.example`. Интерфейс уже выбирает `answerApi`; отсутствие ключа не подменяется демо-ответом.
2. **Текущая сессия.** В `lib/auth.ts` есть адаптер проверки: `POST BUHEXPERT_SESSION_VERIFY_URL` с Bearer `BUHEXPERT_SESSION_VERIFY_KEY`, JSON `{ sessionId }`. Ожидается `{ authenticated: true, userId: "стабильный ID" }` либо отказ. Это контракт нового адаптера, **не обнаруженный действующий API Бухэксперта**. Нужно реализовать его на стороне системы или заменить проверкой существующего провайдера. Cookie берётся по `BUHEXPERT_SESSION_COOKIE`. На отдельном домене Vercel cookie сайта сама не появится: требуется размещение на домене сайта или согласованный SSO.
3. **Регистрация и вход.** Подключить существующую форму/SDK в `AuthDialog` и `siteAuth.authenticate`, подтвердить серверную сессию и вызвать существующий `onSuccess`. Он закрывает форму и вызывает только `reveal` сохранённого ответа. Пока контракта нет, реальная форма сообщает о недоступности входа, а `/api/article-assistant/auth` отвечает 501. Демо-аккаунт не принимается реальным API.
4. **База переписок.** Заменить функции `readHistory`, `saveHistory`, `bindHistory` в `lib/article-assistant/history.ts` адаптером постоянной БД. Запись содержит статью, sessionId, requestId, вопрос, полный предыдущий диалог, время, полный ответ и подтверждённый userId. Вопрос записывается перед моделью, ответ — до выдачи клиенту; вход привязывает гостевую запись к пользователю. Нужны общий уникальный ключ и транзакционная идемпотентность для нескольких серверов. Очистка интерфейса не вызывает удаление данных.
5. **Статьи и события.** Подключить серверный текст текущей статьи из CMS. Для реальных событий адаптер умеет вызывать уже загруженный `window.ym` при заданном счётчике; загрузка Метрики/согласия и серверное хранилище событий остаются на стороне сайта. Аналитика не заменяет архив вопросов и ответов.

Для локального или собственного сервера доступен файловый адаптер: задать `ASSISTANT_HISTORY_DIR` как абсолютный путь к постоянному тому вне публичных каталогов. Он хранит JSON на сервере, переиспользует завершённый запрос при повторе и переживает перезапуск. На Vercel этот адаптер намеренно отклоняет конфигурацию: временная файловая система не подходит для постоянной истории. Без переменной запись отключена. Одного изменения переменных окружения недостаточно, чтобы получить полностью рабочий пилот Бухэксперта.
