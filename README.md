# Бухэксперт — прототип помощника в статье, v2

Адаптивная копия статьи о сортировке сотрудников в 1С ЗУП с интерактивным помощником. Next.js 16.4, React 19, TypeScript, CSS Modules. Работает без API-ключа, базы данных и настоящих аккаунтов.

Помощник сохраняет содержание исходного прототипа в белом оформлении Бухэксперта: фиолетовая строка «ИИ-помощник Бухэксперта», бейдж «В контексте статьи», заголовок и описание в светло-сиреневой части, белое поле и кнопка «Спросить ИИ». Три полных вопроса по ЗУП сразу запускают запрос. Ширина всего компонента ограничена 760 px во всех состояниях; он выровнен по левому краю текста статьи. Начальная высота на компьютере — около 414 px, без фиксированной высоты. После отправки появляются вопрос, ответ и исходное предупреждение об ошибках ИИ. Гость видит два законченных предложения и предложение регистрации; вход раскрывает сохранённый ответ в той же карточке. Чат растёт по содержимому до 70% видимой области, затем прокручивается история, шапка и ввод остаются доступны. Стили изолированы в CSS Modules, адаптация зависит от ширины обёртки через container query.

## Запуск и проверка

Node.js 22+ и npm:

```bash
npm ci
npm run dev
```

- `/` и `/articles/sortirovka-sotrudnikov` — статья с помощником.
- `/demo` — девять состояний и локальный журнал событий: посетитель, начало ответа, регистрация, вход, полный ответ, пользователь со входом, длинный диалог, загрузка, ошибка.

```bash
npm run lint
npm run build
npm start
```

Браузерные проверки (Chromium устанавливается один раз):

```bash
npx playwright install chromium
npm run test:e2e
```

Тесты автоматически запускают dev-сервер либо используют уже запущенный. Для опубликованной версии задайте `TEST_URL=https://your-project.vercel.app`. Скриншоты сохраняются в `docs/screenshots/`, трассировки ошибок — в игнорируемой папке `test-results/`.

22 теста покрывают основные сценарии, размеры 2560/2048/1440/1024/768/390/375/360 px, начальную высоту карточки и рост поля при вводе, сохранение фокуса после регистрации и уменьшение видимой области экрана при вводе. Загрузка, ошибка с повтором, длинная история и клавиатурная прокрутка дополнительно проверяются на 1440/1024/390 px. Эмуляция уменьшенного viewport не заменяет проверку экранной клавиатуры на физическом телефоне. Контраст белого текста основной кнопки — 6.45:1. Финальные экраны без панели разработчика: `docs/screenshots/ux-*.png`, внутри статьи — `docs/screenshots/restored-*-page.png`, полная страница с начальным состоянием и длинным диалогом — `docs/screenshots/restored-*-full-page.png`. Для повторной съёмки запустите production-сервер на порту 3002 и `node scripts/capture-assistant.mjs` (либо задайте `CAPTURE_URL`).

## Что работает

- Все три примера сразу отправляют полный вопрос; свой вопрос отправляется кнопкой «Спросить ИИ». Во время запроса повторная отправка недоступна.
- Гость получает законченные предложения; продолжение возвращается отдельным серверным запросом после тестового входа, без повторной генерации.
- Закрытие формы сохраняет вопрос; вход и регистрация учитываются раздельно.
- Markdown, уточняющие вопросы, внутренняя прокрутка, сохранение позиции чтения, новый диалог, ошибка и повтор с сохранением черновика.
- Клавиатурный фокус в форме, доступные подписи, размеры 1440/768/390/360 px.
- Новая сессия при обновлении страницы. Исходная группа неизменна; новый диалог не сбрасывает счётчик вопросов. Просмотр блока учитывается после непрерывной видимости 50% в течение секунды.

## Что демонстрируется

Ответы — предсказуемые серверные примеры по статье, а не работа модели. Регистрация и вход не создают аккаунты и не отправляют поля формы или письма. Аналитика хранится только в памяти страницы и передаётся через локальный `CustomEvent` `buhexpert:demo-event`; внешние счётчики не подключены. Поиск ограничен демонстрационной статьёй. Ссылки на материалы ведут на настоящий Бухэксперт.

## Подключение реальных сервисов

| Часть | Файлы и назначение |
| --- | --- |
| Интерфейс | `components/article-assistant/Assistant.tsx`, CSS Modules, `AuthDialog.tsx` |
| Контекст статьи | `data/sorting-article.ts`; передаётся в компонент отдельно |
| Контракты | `lib/article-assistant/contracts.ts`: `AnswerAdapter`, `AuthAdapter`, `AnalyticsAdapter` |
| Демо | `lib/article-assistant/client.ts`, `fixtures.ts`, `/api/demo-assistant/*` — только публичные примеры |
| Реальный API | `answerApi` → `/api/article-assistant`, `handler.ts` → `lib/ai.ts`; сохраняет системный промпт, текст статьи и историю с ролями user/assistant |
| Авторизация | Заменить тестовый `AuthAdapter` и подключить проверку серверной сессии в `lib/auth.ts`; наличие cookie не даёт доступ |
| Аналитика | Подключить собственный `AnalyticsAdapter` к хранилищу; журнал `/demo` предназначен для проверки событий |

`ArticlePrototype` намеренно использует `demoApi` и `demoAuth`. Одного изменения переменных недостаточно для реальной авторизации: требуется подключить адаптеры сайта и подтверждённую начальную сессию, заменить тестовую форму. Демонстрационные токены не принимаются реальным API.

Для серверной интеграции предусмотрены переменные из `.env.example`: `ASSISTANT_MODE=real`, `AUTH_MODE=real`, `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`, приватный `ASSISTANT_TOKEN_SECRET`. Секреты хранятся только на сервере. Для реального пилота задайте `ASSISTANT_ENABLED=true` и `ASSISTANT_PILOT_START` в ISO 8601: через 24 часа блок скрывается и новые запросы отклоняются. Отключение не удаляет данные; постоянное хранение переписок и событий ещё требуется подключить. `/demo` доступна независимо от пилота.

Ответ для раскрытия переносится в зашифрованном билете с привязкой к сессии и сроком 24 часа. У демонстрации публичный ключ для публичных примеров; для реальных ответов обязателен приватный секрет. Перед настоящим пилотом нужны серверное ограничение частоты запросов, общая идемпотентность, хранилище и проверенный провайдер авторизации.
